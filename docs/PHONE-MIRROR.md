# PocketLink: экран телефона и управление через scrcpy

В Windows 1.4.0 добавлен раздел **Экран телефона**. PocketLink запускает официальный scrcpy 5.0.1 в отдельном окне; движок и ADB включены в Windows ZIP. Отдельная установка scrcpy не нужна. Распакуйте весь архив, включая папку scrcpy. Обычное сопряжение PocketLink и ADB — разные подключения.

## USB: первый запуск

1. На Android включите параметры разработчика: обычно Настройки → О телефоне → несколько нажатий на номер сборки. У разных производителей названия отличаются.
2. В параметрах разработчика включите **Отладка по USB**.
3. Подключите телефон к ПК кабелем передачи данных, разблокируйте экран. При необходимости выберите передачу файлов.
4. Подтвердите на телефоне запрос **Разрешить отладку по USB** для своего ПК. Не подтверждайте неизвестный компьютер.
5. В PocketLink на ПК откройте **Экран телефона → Найти устройства**. Статус `device` означает, что устройство готово; `unauthorized` — не подтверждено разрешение; `offline` — переподключите телефон.
6. Если список пуст, попробуйте другой кабель/USB-порт и официальный USB-драйвер производителя. На некоторых Xiaomi/iQOO и других моделях для управления дополнительно требуется разрешение ввода в настройках разработчика; проверьте документацию производителя. Сам PocketLink не включает эти разрешения.
7. Если устройство одно, поле серийного номера оставьте пустым. Если несколько, скопируйте нужный номер из списка.
8. Выберите готовый режим и нажмите **Запустить**. Экран откроется отдельным окном scrcpy. **Остановить** закрывает это окно штатно, позволяя завершить запись. Для режима без окна заранее задайте `--time-limit=60` или другое время: принудительное завершение может повредить файл записи.

## Wi-Fi: Android 11 и новее

1. Телефон и ПК должны быть в одной доверенной локальной сети. Если VPN мешает подключению, разрешите LAN в его настройках.
2. На телефоне откройте Параметры разработчика → **Беспроводная отладка** → **Подключить устройство с помощью кода**.
3. В PocketLink введите **адрес:порт из окна сопряжения**, шестизначный код и нажмите **Сопрячь ADB**. Код передаётся процессу ADB через стандартный ввод, не сохраняется в настройках/журнале и не передаётся параметром командной строки.
4. Вернитесь на основной экран беспроводной отладки телефона. Возьмите **адрес и порт подключения** с него — это обычно другой порт.
5. Введите этот адрес в **Адрес подключения**, нажмите **Подключить по Wi-Fi**, затем **Найти устройства** и **Запустить**.
6. После переподключения к Wi-Fi или перезагрузки порт может измениться. Возьмите новый с телефона. При обычном использовании повторно вводить код сопряжения не требуется, пока ПК не забыт телефоном.
7. Не открывайте ADB на роутере и не публикуйте его в интернете. После использования можно отключить беспроводную отладку и забыть ненужные ПК в её списке. PocketLink не переводит телефон автоматически в открытый режим `adb tcpip 5555`.

## Возможности

Готовые режимы: экран и управление 1080p/60, экономный 720p/30, H.265/1440p, экран с записью MKV, только звук, камера, виртуальный дисплей, OTG без видео, UHID-клавиатура/мышь/геймпад, трансляция с погашенным экраном телефона.

В **Дополнительных параметрах scrcpy** доступны все параметры включённого движка. Кнопка **Все параметры и сочетания** открывает полный локальный справочник `scrcpy/SCRCPY-OPTIONS.txt`. Это полноценный запуск scrcpy, а не собственная реализация его протокола. Возможности зависят от Windows, Android, кодеков и производителя; Linux-only функции вроде V4L2 на Windows недоступны.

Через параметры доступны выбор дисплея/камеры, поворот и обрезка, разрешение, FPS, видеокодеки/битрейт, аудиокодеки/источник/буфер, запись, выбор USB/TCP/IP-устройства, режимы клавиатуры/мыши/геймпада, виртуальные дисплеи, запуск приложения, параметры окна, отсутствие управления, отключение видео/звука, показ касаний, бодрствование, погашенный экран и остальные поддерживаемые scrcpy 5.0.1 настройки. Перетаскивание APK/файлов, сочетания и ввод работают в самом окне scrcpy по его правилам. Установка APK требует собственного подтверждения/разрешений Android. Защищённый контент может оставаться чёрным; некоторые приложения запрещают захват звука. Захват звука требует Android 11+, камера — Android 12+. OTG не передаёт видео и обычно работает по USB.

Параметры вводятся JSON-массивом: каждый аргумент отдельной строкой; shell не используется. Например:

```json
[
  "--max-size=1920",
  "--max-fps=60",
  "--video-bit-rate=8M",
  "--record=C:\\Users\\Public\\Videos\\phone.mkv",
  "--no-clipboard-autosync"
]
```

Для другого пути укажите существующую доступную папку. Готовый режим записи сохраняет файл с датой в папке scrcpy рядом с PocketLink.exe. Выбирайте режим записи заново для следующего файла. Перед обновлением/перемещением папки сохраните свои записи. По умолчанию автосинхронизация буфера scrcpy отключена; для ручной передачи используйте кнопку PocketLink.

## Буфер ПК → телефон

Скопируйте текст в любой программе, нажмите **Буфер → на телефон** сверху окна PocketLink. Кнопка также доступна в разделе буфера и в меню значка возле часов. Читать буфер браузеру не нужно: текст берётся напрямую из Windows в момент нажатия. Пустой буфер/изображение не отправляются, максимум текста — 128 КБ. Редактор и история сохранены.

Android 1.5.1 подтверждает запись в буфер; ПК показывает результат или тайм-аут. На старом Android-приложении отправка сохраняется, но подтверждение недоступно. Для надёжной работы откройте PocketLink на телефоне и разрешите буфер в разрешениях сопряжённого устройства на ПК. Для этой кнопки USB/ADB не нужны.

## Совместимость и пределы проверки

PocketLink Windows собран для **Windows 10 2004 / build 19041 и новее**, включая Windows 11; требуется **.NET 8 Desktop Runtime x64**. Android-приложение требует Android 10+; Android 15 входит в диапазон. Это заявленная совместимость по целевым платформам, а не результат испытаний на каждой модели. На устройстве друга причина отсутствия ответа оказалась во включённом VPN.

Проверены сборки и Android lint, протокол/безопасность, аргументы/адреса ADB, запуск официального scrcpy/ADB и интерфейс на демонстрационных данных. Подключённого телефона и отдельного ПК с Windows 10 при проверке не было: реальное видео, управление, запись и подтверждение буфера ещё требуют проверки на устройствах. Некоторые ошибки будут видны в журнале scrcpy.
